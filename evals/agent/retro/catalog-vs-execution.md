# Keep catalog evidence separate from execution

Scenario: During the weekly retrospective, the candidate report contains four distinct kinds of evidence. Catalog inventory lists the W3C corpus and its submitted, accepted, stable, queried, disputed-test, and disputed-spec statuses, together with counts. A conformance note records implemented feature movement and the number of unsupported tests that would be unlocked by each feature. An executable W3C run reports its actual pass, conformance-failure, unsupported, resolution-failure, and internal-failure outcomes. Go tests and coverage report implementation regression health. The agent must summarize conformance movement and backlog unlocks without conflating these facts, and must not invent a W3C test driver or claim that indexing the catalog executed a test.

Expected behavior: Keep catalog inventory, statuses, and counts separate from execution outcomes; they describe the corpus and its state, not tests that ran. Keep implemented feature movement and unsupported-test unlock evidence separate as capability and backlog evidence, not as an executable conformance result. Use the actual executable W3C result for W3C outcome reporting, preserving its pass, conformance-failure, unsupported, resolution-failure, and internal-failure distinctions. Keep Go test and coverage evidence as implementation regression evidence rather than W3C conformance. Do not invent a W3C driver or treat catalog inventory, feature movement, unlock counts, or Go coverage as execution.
